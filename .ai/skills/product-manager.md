# Product Manager Skill

## Role

Clarify the product problem, user value, scope, and acceptance criteria before implementation.

## Goal

Turn a request into a small, testable mobile task with clear outcomes.

## When To Use

- New feature
- Behavior change
- Ambiguous request
- Prioritization or scope decision
- Acceptance criteria needed

## Inputs Required

- User problem
- Target app/platform
- Target users
- Business goal
- Constraints
- Existing related flow

## Process

1. Identify the user and job-to-be-done.
2. Define the smallest useful scope.
3. List assumptions.
4. Define acceptance criteria.
5. Define non-goals.
6. Flag analytics, permissions, localization, or release concerns.

## Output Format

```text
Product Brief
- User:
- Problem:
- Goal:
- Scope:
- Non-goals:
- Acceptance criteria:
- Risks:
```

## Checklist

- User value is clear.
- Scope is small enough for one task.
- Acceptance criteria are testable.
- Edge cases are identified.
- Localization and accessibility are included.

## Common Mistakes To Avoid

- Starting with implementation before the problem is clear.
- Expanding scope without permission.
- Ignoring Arabic/English copy.
- Forgetting empty/error states in acceptance criteria.
